Clase 9 — Selectores CSS y regla de cascada

En la clase anterior aprendimos a escribir reglas CSS y a aplicarlas de tres formas: en un archivo externo, en un bloque <style> y con el atributo style. Todas las reglas usaban un selector de elemento, es decir, el nombre de una etiqueta. Hoy vamos a aprender a escoger con precisión qué elementos reciben cada estilo, y a predecir cuál regla gana cuando varias se contradicen.

Desde esta clase, cada taller avanza el front end de su proyecto PIA siguiendo el lienzo de su equipo. Hoy le toca la barra superior y la tabla de registros con estados en color.

Repaso: lo que ya sabemos de CSS

Una regla CSS tiene un selector y un bloque de declaraciones entre llaves. Cada declaración es una pareja propiedad: valor terminada en punto y coma:

p {
    color: #333333;
    font-size: 16px;
}

Cuando dos reglas le piden cosas distintas a un mismo elemento sobre la misma propiedad, el navegador aplica la cascada. Lo que vimos el viernes 2 de octubre fue la versión más sencilla: el estilo en línea gana, y entre las hojas externa y embebida gana la que aparezca de última en el documento. Hoy esa regla se completa.

Verifique: el <link> a estilos.css va antes del <style>. Ambos definen color para h2, y el h2 no tiene atributo style. ¿Qué color se ve?

El problema: el selector de elemento afecta a todos

Suponga que en una tabla de préstamos de equipos quiere ver en rojo solo las filas de los equipos atrasados. Con lo que sabemos hasta ahora, la única opción sería escribir una regla para tr, pero esa regla pintaría de rojo todas las filas de todas las tablas de la página. El selector de elemento no distingue entre una fila y otra: para él, todas las tr son iguales.

Lo mismo pasa con los enlaces. En una página normal hay enlaces en el menú de la barra superior, enlaces dentro del texto y enlaces en el pie de página. Casi nunca deben verse igual: los del menú suelen ir en blanco sobre fondo oscuro y sin subrayado, y los del texto suelen mantener el subrayado para que se reconozcan. Una regla para a los cambia todos a la vez.

CSS resuelve esto con otros tipos de selector. Hoy veremos tres nuevos: el selector de clase, el selector de id y el selector descendiente. Con ellos y con el selector de elemento que ya conocemos, se puede apuntar a casi cualquier parte de una página sin tocar los demás elementos.

Selector de clase

Una clase es una etiqueta que usted le pone a los elementos que quiere tratar igual. Se asigna en el HTML con el atributo class, y en el CSS se escribe con un punto delante del nombre:

HTML

<tr class="atrasado">
    <td>Portátil 07</td>
    <td>Atrasado</td>
</tr>
<tr class="devuelto">
    <td>Video proyector 2</td>
    <td>Devuelto</td>
</tr>

CSS

.atrasado {
    color: darkred;
    background-color: #FBE3E6;
}

.devuelto {
    color: darkgreen;
}

La regla .atrasado se aplica a cualquier elemento que tenga class="atrasado", sea una fila, un párrafo o una celda. Las demás filas no se afectan. Observe que el punto va solo en el CSS: en el atributo class se escribe el nombre sin punto.

Una clase se puede repetir

La misma clase se puede usar en todos los elementos que se quiera. Si la tabla tiene veinte préstamos atrasados, las veinte filas llevan class="atrasado" y todas quedan en rojo con una sola regla. Si mañana se decide que lo atrasado se marca en naranja, se cambia una línea del CSS y no se toca el HTML.

Un elemento puede tener varias clases

El atributo class acepta varios nombres separados por espacio. El elemento recibe los estilos de todas sus clases:

<tr class="fila atrasado">

Esa fila recibe lo que diga .fila (por ejemplo, el tamaño de letra de todas las filas) y además lo que diga .atrasado (el color del estado). Es un error frecuente escribir el atributo dos veces, class="fila" class="atrasado": el navegador solo toma el primero e ignora el segundo, sin avisar. También es un error separar con comas: class="fila, atrasado" crea una clase llamada fila, que no coincide con ninguna regla.

Cómo nombrar las clases

  • Use nombres que digan qué es o en qué estado está el elemento, no cómo se ve: .atrasado es mejor que .rojo. Si el color cambia, el nombre .rojo quedaría mintiendo.
  • Escriba en minúsculas y separe las palabras con guion: .en-proceso, .barra-usuario. Las clases distinguen mayúsculas: .Atrasado y .atrasado son clases distintas.
  • No use espacios (el espacio separa clases), no empiece el nombre con un número y evite tildes y la letra ñ, que pueden dar problemas en algunos editores.

Selector de id

El atributo id ya lo conocemos: en la Clase 4 lo usamos para conectar un <label> con su <input> mediante el atributo for. Un id identifica a un solo elemento: su valor no se puede repetir dentro de la misma página. En CSS se selecciona con un numeral delante del nombre:

HTML

<header id="barra-superior">
    <h1>Préstamo de Equipos</h1>
    <p>Usuario: Coordinación</p>
</header>

CSS

#barra-superior {
    background-color: #132A4C;
    color: white;
}

Como el id es único, el selector #barra-superior apunta exactamente a un elemento. Por eso se usa para las piezas que aparecen una sola vez en la página: la barra superior, el menú principal, el formulario de registro. Si se pone el mismo id a dos elementos, el navegador normalmente pinta los dos y no muestra error, pero el documento queda inválido y más adelante JavaScript solo encontrará el primero. Para lo que se repite, la herramienta correcta es la clase.

Selector descendiente

El selector descendiente combina dos selectores separados por un espacio. Se lee de derecha a izquierda: nav a significa "los enlaces que estén dentro de un nav".

HTML

<nav>
    <ul>
        <li><a href="#">Inicio</a></li>
        <li><a href="#">Préstamos</a></li>
    </ul>
</nav>
...
<footer>
    <p><a href="#">Reglamento</a></p>
</footer>

CSS

nav a {
    color: white;
    text-decoration: none;
}

footer a {
    color: #2C5C8F;
}

Los enlaces del menú quedan blancos y sin subrayado; el enlace del pie queda azul y conserva su subrayado. Ninguno de los dos se afecta con la regla del otro.

Dos detalles importantes:

  • "Dentro" significa a cualquier profundidad. En el ejemplo, los a no son hijos directos de nav: están dentro de li, que está dentro de ul, que está dentro de nav. Aun así, nav a los selecciona.
  • El espacio cambia el significado. En un selector descendiente, el espacio es parte de la sintaxis. #barra-superior p (con espacio) es "los párrafos dentro de la barra"; sin espacio sería otra cosa que no vamos a usar en este curso.

El selector descendiente se puede armar con cualquiera de los tipos que conocemos: #barra-superior p, .atrasado td, table th. Es la forma más limpia de dar estilo a lo que está dentro de una pieza sin llenar el HTML de atributos class.

Dos propiedades nuevas

A las cinco propiedades de la clase pasada se suman dos, que se necesitan para la barra y los menús. En el taller de hoy se aceptan estas siete.

PropiedadQué cambiaValores que usaremos
font-weightGrosor de la letrabold (negrita), normal
text-decorationLínea decorativa del textonone (quita el subrayado de los enlaces), underline

font-weight: normal sirve, por ejemplo, para quitar la negrita que el navegador pone por defecto en los th o en los títulos. text-decoration: none se usa casi siempre en los enlaces de un menú, donde el subrayado sobra porque el lugar ya indica que son enlaces.

Por qué los enlaces no heredan el color de la barra

En la Clase 8 vimos que color se hereda: si se pone color: white en la barra, el título y los párrafos que estén adentro se vuelven blancos. Pero los enlaces siguen azules. La razón es que el navegador ya trae su propia regla que apunta directamente a a (azul y subrayado), y un valor heredado siempre pierde frente a cualquier regla que apunte directamente al elemento, aunque sea la del navegador. La solución es escribir una regla para los enlaces de la barra: #barra-superior a { color: white; }.

La cascada completa: especificidad

  
Ahora que existen varios tipos de selector, puede pasar que una regla de elemento, una de clase y una de id apunten al mismo elemento y le pidan colores distintos. El orden en el documento ya no basta para decidir. El navegador sigue estos pasos, en este orden:

  
    
    
  1. Estilo en línea. Si el elemento tiene atributo style con esa propiedad, gana. Es lo mismo que vimos en la Clase 8.
    2. 
    
  2. Especificidad. Entre las reglas de las hojas externa y embebida, gana la del selector más específico, sin importar dónde esté escrita.
    3. 
    
  3. Orden. Solo si dos reglas tienen exactamente la misma especificidad, gana la que aparece de última.
    4. 
  

  
La especificidad es una medida de qué tan precisa es la puntería de un selector. De mayor a menor: un id es más específico que una clase, y una clase es más específica que un elemento. La razón es lógica: p apunta a todos los párrafos, .aviso solo a los que tienen esa clase, y #aviso-principal a uno solo.

  

    
Orden de fuerza: estilo en línea > id > clase > elemento. Si empatan, gana la última regla escrita.

  


  
Cómo se cuenta la especificidad

  
Un selector descendiente combina varios selectores, así que se cuenta por columnas: cuántos id, cuántas clases y cuántos elementos tiene. Para comparar dos selectores se mira primero la columna de id: el que tenga más, gana. Si empatan, se mira la de clases; si vuelven a empatar, la de elementos.

  

  

    
SelectorIdClasesElementosSe escribe

    
      
a0010-0-1

      
nav a0020-0-2

.atrasado td0110-1-1

      
#barra-superior1001-0-0

      
#barra-superior a1011-0-1

    
  

  

  
Fíjese en que .atrasado (0-1-0) le gana a nav a (0-0-2): una sola clase pesa más que cualquier cantidad de elementos, porque la columna de clases se compara antes. Las columnas no se suman entre sí como un número de tres cifras en el que diez elementos valgan lo que una clase.

Ejemplo resuelto

  

    
HTML
<p id="aviso-principal" class="aviso">
    Devolución hasta las 5:00 p. m.
</p>

    
CSS (en este orden)
#aviso-principal {
    color: navy;
}

.aviso {
    color: darkred;
}

p {
    color: black;
}

  

  
El párrafo queda navy. Las tres reglas apuntan al mismo elemento y a la misma propiedad. La regla p está de última, pero eso no importa: el orden solo desempata reglas de igual especificidad. Gana #aviso-principal (1-0-0) frente a .aviso (0-1-0) y frente a p (0-0-1). Si se borra la regla del id, el párrafo queda darkred, porque la clase le gana al elemento aunque el elemento esté después.

Una recomendación práctica

  
Como el id pesa tanto, una regla de id es difícil de corregir después: para ganarle hace falta otro id o un estilo en línea. Por eso en los proyectos reales se prefiere dar estilo con clases y dejar los id para identificar piezas únicas (y, más adelante, para JavaScript). En el taller de hoy usará un id para la barra superior, que es única, y clases para los estados de su tabla, que se repiten.


  
Ver la cascada en el navegador

  
Las herramientas de desarrollador muestran exactamente qué regla ganó. Abra su página, haga clic derecho sobre el elemento y elija Inspeccionar (o presione F12). En el panel Estilos (Styles) aparecen todas las reglas que apuntan a ese elemento, ordenadas de la más fuerte (arriba) a la más débil (abajo). Las declaraciones que perdieron aparecen tachadas. Al final aparece la hoja del navegador, rotulada como user agent stylesheet, que es la que pone azules y subrayados los enlaces.

  

    
Cuando un estilo "no funciona": revise primero si la regla aparece en el panel. Si no aparece, el selector no coincide con el elemento (falta el punto o el numeral, el nombre de la clase está mal escrito, o falta el atributo en el HTML). Si aparece tachada, la regla sí coincide pero otra más específica le está ganando.
