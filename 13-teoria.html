Clase 13 — Introducción a JavaScript: variables, la página y el ingreso por rol

Con el Examen intermedio 2 se cerró el bloque de CSS y diseño responsivo. Hoy empieza el bloque de JavaScript, que va hasta el cierre del módulo. Sus proyectos ya tienen una pantalla de ingreso y un panel que se ven bien en computador y en celular, pero no hacen nada: el botón INGRESAR siempre lleva a la misma página, sin importar el rol que se elija. Al terminar la clase de hoy, la pantalla de ingreso de su proyecto llevará a una página distinta según el rol, y el panel mostrará datos que vienen de variables.

Tres lenguajes, tres trabajos

Una página web moderna se construye con tres lenguajes que se reparten el trabajo:

LenguajeTrabajoPregunta que responde
HTMLEstructura y contenido¿Qué es cada cosa? (un título, un formulario, una tabla)
CSSPresentación¿Cómo se ve? (colores, tamaños, distribución)
JavaScriptComportamiento¿Qué hace la página cuando el usuario actúa? (clic, escribir, enviar)

JavaScript es un lenguaje de programación. HTML y CSS describen; JavaScript da instrucciones que el navegador ejecuta una tras otra: guardar un dato, compararlo, cambiar un texto de la página, abrir otra página.

Fue creado por Brendan Eich en 1995 en la empresa Netscape, para su navegador. Hoy el lenguaje está estandarizado por Ecma International con el nombre de ECMAScript (norma ECMA-262), y todos los navegadores actuales lo ejecutan sin instalar nada.

Java no es JavaScript. Se parecen en el nombre por una decisión comercial de la época, pero son lenguajes distintos. Java se usa, entre otras cosas, para aplicaciones de escritorio, de servidor y de Android, y necesita instalarse y compilarse. JavaScript corre dentro del navegador. En este curso trabajamos solo con JavaScript.

Verifique: Su panel debe mostrar un mensaje cuando el usuario hace clic en un botón. ¿Qué lenguaje se encarga de eso?

Dónde se escribe JavaScript

Igual que con CSS, el código JavaScript puede ir dentro de la página o en un archivo aparte. Usaremos siempre el archivo externo, por la misma razón que usamos estilos.css: el HTML queda limpio y el mismo archivo sirve para varias páginas.

El archivo tiene extensión .js y se conecta con la etiqueta <script> y el atributo src (de source, fuente):

<body>
    <h1>Préstamo de equipos</h1>
    <p id="saludo"></p>

    <script src="app.js"></script>
</body>

Tres detalles que causan la mayoría de errores del primer día:

  1. La etiqueta va al final del <body>, justo antes de </body>. El navegador lee la página de arriba hacia abajo. Si el script está en el <head>, se ejecuta antes de que existan los elementos de la página, y cuando el código busca el párrafo saludo no lo encuentra.
  2. <script> siempre lleva cierre, aunque no tenga nada adentro. <script src="app.js"> sin </script> no funciona.
  3. El nombre del archivo en src debe coincidir exactamente con el archivo real, incluidas mayúsculas. App.js y app.js son archivos distintos cuando la página se publica.

Una página puede tener varios <script>, y un mismo archivo .js puede estar enlazado desde varias páginas. En el taller usará dos: ingreso.js para la pantalla de ingreso y panel.js para las páginas de panel.

La consola del navegador

JavaScript no muestra sus errores en la página: los muestra en la consola, una herramienta que trae el navegador. Para abrirla, presione F12 (o clic derecho, Inspeccionar) y elija la pestaña Consola. Desde hoy, la consola debe estar abierta siempre que trabaje con JavaScript.

La instrucción console.log() escribe en la consola lo que se le ponga entre paréntesis. Sirve para comprobar que el archivo quedó bien enlazado y para ver el valor de un dato mientras el programa corre:

console.log("app.js está conectado");

Si recarga la página y ese mensaje no aparece en la consola, el archivo no está enlazado: revise la ruta en src. Si aparece un mensaje en rojo, es un error: la consola indica el archivo y el número de línea donde está.

Variables: guardar datos con nombre

Una variable es un espacio de memoria con un nombre, donde el programa guarda un dato para usarlo después. Piense en una caja con una etiqueta: la etiqueta es el nombre y lo que hay adentro es el valor.

let equiposPrestados = 12;
const nombreSala = "Sala de informática 2";

La línea se lee así: cree una variable llamada equiposPrestados y guarde en ella el valor 12. El signo = en JavaScript no significa "es igual": significa asignar, es decir, guardar el valor de la derecha en la variable de la izquierda.

let, const y var

PalabraCuándo se usa¿Se puede cambiar el valor después?
letDatos que pueden cambiar mientras el programa corre (una cantidad, un estado)Sí
constDatos que no deben cambiar (el nombre del sistema, un código, una meta fija)No. Si se intenta, la consola muestra un error
varForma antigua, anterior a 2015. Aparece en código viejo y en muchos tutorialesSí, pero tiene comportamientos que causan errores difíciles de encontrar
 
let equiposPrestados = 12;
equiposPrestados = 13;          // correcto: let permite cambiar el valor

const nombreSala = "Sala de informática 2";
nombreSala = "Sala 3";          // error: no se puede reasignar una const

Regla del curso: use const por defecto y let solo cuando el valor vaya a cambiar. var se explica para que la reconozca cuando la vea, pero en sus archivos no la use.

Cómo nombrar una variable

  • Empieza con una letra; puede tener letras y números, pero no espacios ni guiones.
  • Se usa el estilo camelCase: la primera palabra en minúscula y cada palabra siguiente con mayúscula inicial: horasRegistradas, menuDelDia, torneoActivo.
  • Mayúsculas y minúsculas importan: total y Total son dos variables distintas.
  • Evite tildes y la ñ en los nombres. JavaScript las acepta, pero causan confusiones al escribir. Los valores sí pueden llevar tildes: const zona = "Lab. física";
  • El nombre debe decir qué guarda: racionesEntregadas se entiende; x o dato1 no.

Tipos de dato

Cada valor tiene un tipo, y el tipo decide qué se puede hacer con él. Hoy usamos tres:

TipoQué guardaCómo se escribeEjemplo
string (texto)Palabras, frases, códigosEntre comillas dobles o sencillas"Portátil 07"
number (número)Cantidades, enteras o con decimalesSin comillas. El decimal se escribe con punto12, 4.5
boolean (lógico)Solo dos valores: verdadero o falsotrue o false, sin comillastrue

La instrucción typeof dice el tipo de un valor. Es útil en la consola cuando algo no funciona como se espera: console.log(typeof equiposPrestados); muestra number.

Cuidado con las comillas. 12 es un número; "12" es un texto que contiene los caracteres 1 y 2. De la misma forma, true es un booleano y "true" es un texto. Las comillas cambian el tipo.

Unir textos: concatenación

El operador + entre textos los une en uno solo. Esto se llama concatenar, y es la forma de armar mensajes con datos guardados en variables:

const sala = "Sala 2";
let disponibles = 8;
console.log("En la " + sala + " hay " + disponibles + " equipos disponibles");
// En la Sala 2 hay 8 equipos disponibles

Observe los espacios dentro de las comillas: el + no agrega espacios por su cuenta. Y cuando se une un texto con un número, el resultado es texto: "5" + 5 da "55", no 10. Los cálculos con números se estudian en la próxima clase.

Ventanas del navegador: alert y prompt

El navegador trae dos ventanas sencillas que se manejan desde JavaScript:

alert("Préstamo registrado");                  // muestra un aviso con botón Aceptar
const nombre = prompt("¿Cómo se llama?");       // pide un dato y lo guarda

alert detiene la página hasta que el usuario presiona Aceptar. prompt devuelve lo que el usuario escribió siempre como texto (aunque escriba un número). Son útiles para pruebas rápidas, pero en una aplicación real los mensajes se muestran dentro de la página, como veremos enseguida.

JavaScript y la página: getElementById

Para que JavaScript cambie algo de la página, primero tiene que encontrar el elemento. La forma más directa es por su id, el mismo atributo que ya usa en CSS con el selector #:

<p>Equipos disponibles: <strong id="total-disponibles"></strong></p>
let disponibles = 8;
document.getElementById("total-disponibles").textContent = disponibles;
  • document es la página completa.
  • getElementById("total-disponibles") busca el elemento con ese id. Va sin #: el numeral es de CSS.
  • .textContent es el texto que hay dentro del elemento. Al asignarle un valor con =, ese texto se reemplaza.

Si el id está mal escrito o el script está en el <head>, la consola muestra un error parecido a Cannot set properties of null: significa que el elemento no se encontró.

Para leer lo que el usuario escribió en un campo de formulario (input o select) se usa .value en lugar de .textContent:

const usuario = document.getElementById("usuario").value;

Cuando un elemento se va a usar varias veces, es más claro guardarlo en una const:

const mensaje = document.getElementById("mensaje");
mensaje.textContent = "Préstamo registrado";

Eventos: reaccionar a una acción del usuario

Hasta aquí el código se ejecuta una sola vez, cuando carga la página. Para que algo pase cuando el usuario hace clic, se usa addEventListener (agregar un "escuchador" de eventos):

<button type="button" id="btn-prestar">Registrar préstamo</button>
<p id="mensaje"></p>
const botonPrestar = document.getElementById("btn-prestar");

botonPrestar.addEventListener("click", function () {
    document.getElementById("mensaje").textContent = "Préstamo registrado en la Sala 2";
});

Se lee así: al botón btn-prestar, cuando ocurra el evento click, ejecútele las instrucciones que están entre las llaves. Lo que va entre function () { y } no se ejecuta al cargar la página: queda esperando el clic. El nombre técnico de ese bloque es función; las funciones se estudian a fondo al final del módulo, por ahora basta con copiar la forma exacta.

La etiqueta <button> entra hoy a lo visto en clase. Lleva type="button" para indicar que es un botón para JavaScript y no un botón de envío de formulario.

El evento submit y preventDefault

Un formulario dispara el evento submit cuando se presiona su botón de envío. Por defecto, el navegador envía el formulario a la página que indique action y la página cambia. Si queremos que JavaScript decida primero qué hacer, hay que detener ese comportamiento por defecto:

const formulario = document.getElementById("form-ingreso");

formulario.addEventListener("submit", function (evento) {
    evento.preventDefault();      // detiene el envío automático
    // aquí JavaScript decide qué hacer
});

evento es la información del suceso que el navegador le entrega a la función, y preventDefault() significa "impida el comportamiento por defecto". Sin esa línea, el navegador cambia de página antes de que su código alcance a tomar la decisión. Como ahora JavaScript decide el destino, el atributo action del formulario de ingreso se quita.

Tomar decisiones: if, else if y else

Hasta ahora el programa siempre hace lo mismo. Con if (si) el programa ejecuta un bloque de instrucciones solo si una condición se cumple:

if (condición) {
    // se ejecuta si la condición es verdadera
} else if (otra condición) {
    // se ejecuta si la primera fue falsa y esta es verdadera
} else {
    // se ejecuta si ninguna de las anteriores se cumplió
}

El navegador revisa las condiciones en orden, de arriba hacia abajo, y ejecuta solo el primer bloque cuya condición sea verdadera; los demás se saltan. Puede haber tantos else if como haga falta, y el else final es opcional.

Comparar con ===

La condición más común compara dos valores con === (tres signos igual), que responde true si son iguales en valor y en tipo:

"docente" === "docente"     // true
"docente" === "Docente"     // false: mayúsculas y minúsculas cuentan
5 === 5                     // true
"5" === 5                   // false: uno es texto y el otro número
usuario === ""              // true si el campo usuario quedó vacío

Correcto

if (rol === "docente") {

Error frecuente

if (rol = "docente") {

Con un solo = no se compara: se asigna "docente" a la variable, y la condición siempre resulta verdadera. Existe también == (dos signos), que compara sin tener en cuenta el tipo; en el curso no lo usamos porque da resultados inesperados.

Ir a otra página: window.location.href

Para que JavaScript lleve al usuario a otra página se asigna la dirección a window.location.href, que es la dirección que aparece en la barra del navegador:

window.location.href = "panel-docente.html";

Funciona igual que hacer clic en un enlace <a href="panel-docente.html">, pero lo decide el programa.

Todo junto: ingreso por rol

El sistema de préstamo de equipos tiene dos roles: Monitor de sala y Docente, y cada uno tiene su propia página de panel. La pantalla de ingreso queda así:

<form id="form-ingreso">
    <label for="usuario">Usuario</label>
    <input type="text" id="usuario">

    <label for="rol">Rol</label>
    <select id="rol">
        <option value="">Seleccione su rol</option>
        <option value="monitor">Monitor de sala</option>
        <option value="docente">Docente</option>
    </select>

    <input type="submit" value="INGRESAR">
</form>

<script src="ingreso.js"></script>

Fíjese en el atributo value de cada option: es lo que JavaScript recibe con .value, no el texto visible. Por eso se escriben cortos, en minúscula y sin tildes. La primera opción tiene value="" (vacío) para detectar que no se eligió rol.

// ingreso.js
console.log("ingreso.js conectado");

const formulario = document.getElementById("form-ingreso");

formulario.addEventListener("submit", function (evento) {
    evento.preventDefault();

    const usuario = document.getElementById("usuario").value;
    const rol = document.getElementById("rol").value;

    if (usuario === "") {
        alert("Escriba su usuario");
    } else if (rol === "monitor") {
        alert("Bienvenido, " + usuario + ". Ingresa como Monitor de sala");
        window.location.href = "panel-monitor.html";
    } else if (rol === "docente") {
        alert("Bienvenido, " + usuario + ". Ingresa como Docente");
        window.location.href = "panel-docente.html";
    } else {
        alert("Seleccione un rol");
    }
});

Siga el recorrido con tres casos: si el usuario queda vacío, se cumple la primera condición y solo sale el aviso; si se escribe lmarin y se elige Docente, la primera condición es falsa, la segunda también, la tercera es verdadera: sale la bienvenida y se abre panel-docente.html; si se escribe usuario pero no se elige rol, ninguna condición se cumple y se ejecuta el else.

¿Por qué la bienvenida sale en un alert y no en el panel? Porque al cambiar de página, las variables de la página anterior se pierden. Llevar datos de una página a otra requiere herramientas que se ven más adelante.

Esto es una simulación, no seguridad

Lo que construimos hoy no protege nada. Cualquier persona puede escribir panel-docente.html en la barra de direcciones y entrar sin pasar por el ingreso, y cualquiera puede leer el archivo ingreso.js desde el navegador. Además, el código no revisa la contraseña. La verificación real de usuario, contraseña y rol se hace en el servidor, con una base de datos, y es tema de Herramientas de Programación II. Hoy el objetivo es aprender cómo un programa toma decisiones y cómo se navega entre las pantallas de cada rol.
