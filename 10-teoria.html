Clase 10 — Modelo de caja y campos de contraseña y archivo

En la clase anterior aprendimos a escoger con precisión qué elementos reciben cada estilo: con selectores de clase, de id y descendientes. Hasta ahora solo hemos cambiado colores, letras y alineación. Hoy vamos a controlar el espacio: cuánto mide cada elemento, cuánto aire tiene por dentro, qué borde lo rodea y qué tan lejos queda de los demás. Esa es la base para armar las tarjetas de un panel y una pantalla de ingreso.

También vamos a ver dos tipos de campo que necesitan sus proyectos: input type="password" y input type="file". En el taller de hoy cada equipo arma la pantalla de ingreso y las tarjetas del panel de inicio de su PIA.

Repaso: selectores de la Clase 9

Una clase se asigna con el atributo class y se selecciona con punto; un id se asigna con id, es único en la página y se selecciona con numeral; el selector descendiente, como #barra-superior a, apunta a los elementos que están dentro de otro. Cuando varias reglas se contradicen, gana la más específica (id > clase > elemento) y, si empatan, la última. Hoy casi todas las reglas usarán clases, porque las tarjetas se repiten.

Verifique: un panel tiene cuatro tarjetas de indicadores iguales. ¿Qué conviene usar para darles estilo a las cuatro con una sola regla?

Todo elemento es una caja

El navegador dibuja cada elemento de la página como un rectángulo. Un párrafo, un título, una tarjeta, un campo de formulario: todos son cajas, aunque no se les vea el contorno. CSS describe esa caja con cuatro capas, desde adentro hacia afuera:

Una forma de recordarlo: piense en un cuadro colgado en la pared. La foto es el contenido; el paspartú blanco que la rodea es el padding; el marco de madera es el border; y la distancia hasta el cuadro de al lado es el margin.

Las cajas en bloque se apilan

Elementos como div, p, h1, header, section o form son de bloque: si no se les da un ancho, ocupan todo el ancho disponible y cada uno empieza en una línea nueva. Por eso las tarjetas que hagamos hoy quedarán una debajo de otra, aunque sean angostas. Es a propósito: en la Clase 11 se ponen en fila con Flexbox, y para eso hay que dominar primero la caja.

Otros elementos, como a, label o img, van en línea: se acomodan uno tras otro dentro del texto, como las palabras de un renglón.

Verifique: ¿Cuál es el orden de las capas de una caja, de adentro hacia afuera?

Ancho y alto: width y height

width fija el ancho de la caja y height su alto. Se pueden dar en píxeles (px), una medida fija, o en porcentaje (%), que se calcula sobre el ancho del elemento que la contiene:

.tarjeta-ingreso {
    width: 320px;      /* siempre 320 píxeles */
}

.tarjeta {
    width: 50%;        /* la mitad del ancho de su contenedor */
}

Si la tarjeta está dentro de un main de 800 px de ancho, width: 50% le da 400 px. Si la pantalla se achica y el main queda de 600 px, la tarjeta pasa a 300 px sola. El porcentaje se adapta; el píxel no.

Cuidado con height. Si el texto no cabe en el alto fijado, se sale de la caja y se monta sobre lo que sigue. En la mayoría de los casos es mejor no fijar el alto y dejar que la caja crezca con su contenido. Use height solo cuando el contenido sea de tamaño conocido.

Verifique: una tarjeta con width: 25% está dentro de un section de 600 px de ancho. ¿Cuánto mide el contenido de la tarjeta?

Padding: el espacio de adentro

El padding separa el contenido del borde. Sin padding, el texto de una tarjeta queda pegado a la orilla y se lee mal. Se puede dar el mismo valor a los cuatro lados o un valor por lado:

Border: el contorno

El borde se escribe casi siempre en forma abreviada, con tres valores separados por espacio: grosor, estilo y color.

.tarjeta {
    border: 1px solid #CBD9E6;
}

Los estilos más usados son solid (línea continua), dashed (guiones) y dotted (puntos). Sin estilo no hay borde: border: 2px navy; no dibuja nada. También se puede poner borde a un solo lado con border-top, border-right, border-bottom o border-left. Un truco muy usado en las tarjetas de indicadores es una franja de color a la izquierda:

.tarjeta {
    border: 1px solid #CBD9E6;
    border-left: 6px solid #2C5C8F;
}
Equipos prestados: 9

Observe que la segunda declaración solo cambia el lado izquierdo: las dos reglas son para el mismo elemento, la del lado izquierdo va después y por eso manda en ese lado.

Esquinas redondeadas: border-radius

border-radius redondea las esquinas de la caja. Con border-radius: 8px; las cuatro esquinas se curvan con un radio de 8 px. Funciona aunque la caja no tenga borde, porque también recorta el color de fondo.

border-radius: 0;
border-radius: 12px;

Verifique: ¿Cuál declaración dibuja un borde?

Margin: el espacio de afuera

El margin separa una caja de las demás. Se escribe igual que el padding: un valor, dos, cuatro, o un lado con margin-top, margin-right, margin-bottom y margin-left. La diferencia es que el margin queda por fuera del borde y no toma el color de fondo.

.tarjeta {
    margin-bottom: 16px;   /* 16 px de separación con la tarjeta de abajo */
}

Centrar una caja: margin auto

Para centrar horizontalmente una caja de bloque, se le da un ancho y margen auto a los lados. El navegador reparte en partes iguales el espacio sobrante entre izquierda y derecha:

.tarjeta-ingreso {
    width: 320px;
    margin: 0 auto;    /* 0 arriba y abajo; auto a izquierda y derecha */
}

Sin width no funciona: una caja de bloque sin ancho ya ocupa todo el espacio, así que no sobra nada para repartir. Tampoco sirve para centrar verticalmente.

Los márgenes verticales se colapsan

Cuando dos cajas de bloque quedan una encima de la otra, el margen de abajo de la primera y el de arriba de la segunda no se suman: se aplica solo el mayor. Si una tarjeta tiene margin-bottom: 20px y la siguiente margin-top: 30px, la separación es de 30 px, no de 50 px. Esto se llama colapso de márgenes y solo ocurre con márgenes verticales, nunca con los horizontales ni con el padding.

Verifique: la tarjeta A tiene margin-bottom: 24px y la tarjeta B, justo debajo, margin-top: 10px. ¿Cuánta separación queda entre ellas?

Verifique: escribió margin: 0 auto; en un div, pero no se centra. ¿Cuál es la causa más probable?

¿Cuánto mide de verdad una caja? box-sizing

Aquí está la trampa más común del modelo de caja. Por defecto, width mide solo el contenido. El padding y el borde se suman por fuera de ese ancho. Ese comportamiento se llama box-sizing: content-box y es el que trae el navegador.

.tarjeta-ingreso {
    width: 300px;
    padding: 20px;
    border: 2px solid #2C5C8F;
}
content-box (por defecto)border-box
Qué mide widthSolo el contenidoContenido + padding + borde
Ancho del contenido300300 − 20 − 20 − 2 − 2 = 256

Con box-sizing: border-box el ancho que usted escribe es el ancho que se ve, y el navegador le quita al contenido lo que ocupen el padding y el borde. Por eso es lo que se usa en casi todos los proyectos:

.tarjeta-ingreso {
    box-sizing: border-box;
    width: 300px;
    padding: 20px;
    border: 2px solid #2C5C8F;
}

Fórmulas para el ancho visible, que también sirven para el alto cambiando izquierda/derecha por arriba/abajo:

content-box: ancho visible = width + padding izquierdo + padding derecho + borde izquierdo + borde derecho.

border-box: ancho visible = width.

En ambos casos: espacio ocupado = ancho visible + margen izquierdo + margen derecho.

Calculadora de caja: cambie los valores y observe cómo cambia la caja y sus medidas. Pruebe la misma combinación con los dos valores de box-sizing.

El problema de los campos que se salen

Los campos de formulario traen su propio padding y borde. Si a un input se le da width: 100% sin border-box, ese 100 % es el ancho del contenido de la tarjeta, y el padding y el borde del campo se suman encima: el campo queda más ancho que el espacio de contenido, se come el padding derecho de la tarjeta y, si ese padding es pequeño, se sale por el borde. Se corrige poniendo box-sizing: border-box también en los campos:

.tarjeta-ingreso input {
    box-sizing: border-box;
    width: 100%;
    padding: 8px;
}

Ver la caja en el navegador

  
Las herramientas de desarrollador dibujan el modelo de caja de cualquier elemento. Haga clic derecho sobre el elemento, elija Inspeccionar (o presione F12) y abra la pestaña Calculado (Computed). Arriba aparece un diagrama con cuatro rectángulos, uno dentro de otro, con los valores reales de margin, border, padding y el tamaño del contenido. Al pasar el puntero sobre el elemento en el panel, la página lo resalta: el contenido en azul, el padding en verde y el margin en naranja.

  
Esta es la forma de comprobar un cálculo: si usted calculó 344 px de ancho visible, en el diagrama debe ver el contenido de 300, 20 de padding y 2 de borde a cada lado. En el taller de hoy le toca hacer esa comprobación con dos elementos de su proyecto.

  

    
Cuando algo "no cabe" o "se sale": inspeccione el elemento y mire el diagrama. Casi siempre la causa es un padding o un borde que se sumó al width porque falta box-sizing: border-box.

  


  
Campo de contraseña: input type="password"

  
Toda pantalla de ingreso tiene un campo para la contraseña. Se escribe como cualquier input, con type="password":

  

    
<label for="clave">Contraseña</label>
<input type="password" id="clave" name="clave"
       placeholder="Mínimo 8 caracteres"
       minlength="8" maxlength="20">

    

      
      
      
Escriba algo: cada carácter se muestra como un punto.

    

  

  

  

    
AtributoQué hace

    
      
placeholderTexto de ayuda en gris dentro del campo vacío. Desaparece al escribir. No reemplaza al label: el rótulo debe seguir existiendo.

      
minlengthMínimo de caracteres. Si el usuario escribió menos, el navegador no deja enviar el formulario y muestra un aviso.

      
maxlengthMáximo de caracteres. El navegador no deja escribir más.

    
  

  

  
placeholder, minlength y maxlength también sirven en los campos type="text" y type="email".


  
Lo que el campo de contraseña hace y lo que no hace

  
El campo password solo oculta en la pantalla lo que se escribe, para que no lo lea alguien que esté mirando. No cifra nada ni protege el dato. Cuando el formulario se envía, la contraseña viaja como texto normal, igual que el usuario. Si el formulario usa method="get", incluso queda escrita en la barra de direcciones.

  
Proteger una contraseña de verdad requiere dos cosas que no dependen del HTML:

  
    
    
  • Que la página se sirva por HTTPS, que cifra los datos mientras viajan entre el navegador y el servidor.
    • 
    
  • Que el servidor no guarde la contraseña tal cual, sino una versión transformada (un resumen o hash), y que verifique al usuario. Eso se aprende en Herramientas de Programación II, con PHP.
    • 
  

  
En Colombia, la Ley 1581 de 2012 obliga a quien recoge datos personales a protegerlos. Por eso los sistemas que manejan información de personas, como sus proyectos PIA, necesitan una pantalla de ingreso, y por eso esa pantalla debe funcionar sobre un servidor seguro cuando el sistema sea real.


  

    
En este módulo nada se guarda ni se verifica. Nuestras páginas son solo HTML, CSS y, más adelante, JavaScript del lado del cliente: no hay servidor ni base de datos. La pantalla de ingreso que arme hoy es una maqueta: se ve como la real, pero no comprueba el usuario ni la contraseña, y al pulsar el botón no se guarda nada. Lo mismo pasa con los archivos del campo de archivo.

Campo de archivo: input type="file"

  
El campo type="file" muestra un botón para escoger un archivo del computador o del celular. En el celular, si el campo acepta imágenes, el teléfono suele ofrecer también la cámara.

  

    
<label for="evidencia">Foto del equipo dañado</label>
<input type="file" id="evidencia" name="evidencia"
       accept="image/*">

    

      
      
    

  

  

  

    
AtributoEjemploQué hace

    
      
acceptaccept="image/*"Solo muestra imágenes en la ventana de selección (jpg, png, etc.).

      
acceptaccept=".pdf"Solo muestra archivos con esa extensión.

      
acceptaccept="image/*,.pdf"Varios tipos, separados por coma.

      
multiplemultiplePermite escoger varios archivos a la vez. Es un atributo sin valor: basta con escribirlo.

    
  

  

  
Ejemplo con varios archivos, para las fotos de una actividad:

  
<label for="fotos">Fotos de la actividad</label>
<input type="file" id="fotos" name="fotos" accept="image/*" multiple>

  

    
accept es una ayuda, no un control de seguridad. En la ventana de selección el usuario puede cambiar el filtro a "Todos los archivos" y escoger otra cosa. El servidor es quien debe revisar que el archivo sea del tipo y tamaño permitidos.

    
Para que un archivo realmente se envíe, el formulario necesita method="post" y el atributo enctype="multipart/form-data", y un servidor que lo reciba y lo guarde. Lo verán en Herramientas de Programación II. Hoy el campo solo se maqueta: el archivo escogido no sale del equipo ni se guarda en ninguna parte.
