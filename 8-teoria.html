Repaso: del contenido a la presentación

En las siete clases anteriores aprendimos a decir qué es cada parte de una página: esto es un título, esto es un menú de navegación, esto es una tabla, esto es un campo de formulario. Eso es la estructura o el contenido, y es el trabajo de HTML.

Lo que HTML no debe hacer es decidir cómo se ve cada parte: de qué color es el título, qué tipo de letra usa el párrafo, si el texto va centrado. Eso es la presentación, y es el trabajo de CSS. Separar las dos cosas tiene una consecuencia práctica muy grande: se puede cambiar por completo el aspecto de un sitio sin tocar una sola etiqueta HTML.

Idea central de la clase: HTML dice qué es cada cosa. CSS dice cómo se ve.

¿Qué es CSS?

CSS son las siglas de Cascading Style Sheets, en español hojas de estilo en cascada. Es un lenguaje distinto de HTML: no tiene etiquetas, sino reglas. Cada regla le dice al navegador: "a estos elementos, aplíqueles estas características visuales".

CSS es un estándar del W3C (World Wide Web Consortium), el mismo organismo que mantiene las especificaciones de HTML. Fue propuesto por Håkon Wium Lie en 1994, y la primera versión (CSS nivel 1) se publicó como recomendación del W3C en diciembre de 1996. Antes de CSS, el aspecto se controlaba con atributos y etiquetas dentro del propio HTML, lo que mezclaba contenido y presentación en el mismo archivo y hacía muy difícil mantener sitios grandes.

La palabra cascada del nombre se refiere a cómo el navegador decide qué estilo aplicar cuando dos o más reglas le piden cosas distintas al mismo elemento. Esa decisión la estudiaremos al final de la teoría de hoy.

Estructura de una regla CSS

Toda regla CSS tiene dos partes: el selector y el bloque de declaraciones.

h1{ color:navy; font-size:32px; }
selectorpropiedadvalor
  • Selector (h1): indica a qué elementos se aplica la regla. Hoy usaremos solo el nombre de la etiqueta: h1, p, body, table. A este tipo se le llama selector de elemento. Los demás tipos de selector se ven en la próxima clase.
  • Llaves { }: encierran todas las declaraciones de la regla.
  • Declaración (color: navy;): una característica visual. Una regla puede tener tantas declaraciones como se necesiten.
  • Propiedad (color): qué característica se va a cambiar.
  • Dos puntos :: separan la propiedad de su valor.
  • Valor (navy): cómo queda esa característica.
  • Punto y coma ;: cierra cada declaración.

Por legibilidad, cada declaración se escribe en su propia línea y con sangría, igual que hacíamos con el HTML anidado:

h1 {
    color: navy;
    font-size: 32px;
}

p {
    color: #333333;
    font-family: Arial, sans-serif;
}

En CSS también hay comentarios, que el navegador ignora. Se escriben entre /* y */. No se usa la forma de HTML (<!-- -->).

/* Estilos de los títulos */
h1 {
    color: navy;
}

Verifique: En la regla p { font-size: 18px; }, ¿qué es 18px?

Errores de sintaxis frecuentes

Cuando el navegador encuentra una declaración mal escrita, no muestra ningún error: simplemente la descarta y sigue con la siguiente. Por eso un error de CSS se nota solo porque "el estilo no se aplicó".

Incorrecto

p {
    color = red;
    font-size: 18px
    background-color: yellow;
}

Correcto

p {
    color: red;
    font-size: 18px;
    background-color: yellow;
}
  • color = red: se usó = en lugar de :. El navegador descarta la declaración.
  • font-size: 18px sin punto y coma: el navegador lee como un solo valor todo lo que sigue hasta el siguiente ;, es decir 18px background-color: yellow. Ese valor no es válido, así que se pierden las dos declaraciones.
  • Si falta la llave de cierre }, las reglas que vienen después pueden quedar "tragadas" dentro de la regla abierta y dejar de funcionar.

Cómo escribir los colores

Hay varias formas de escribir un color. Hoy usaremos dos:

  • Por nombre: CSS reconoce una lista de nombres de colores en inglés (red, blue, navy, white, gray, lightyellow, entre otros). Son cómodos, pero la lista es limitada.
  • Hexadecimal: un numeral seguido de seis dígitos hexadecimales (0 a 9 y A a F), #RRGGBB. Los dos primeros indican la cantidad de rojo, los dos del medio la de verde y los dos últimos la de azul, cada uno de 00 (nada) a FF (máximo). #000000 es negro, #FFFFFF es blanco y #FF0000 es rojo puro.

Por qué font-family lleva varias fuentes

El navegador solo puede usar un tipo de letra que esté instalado en el equipo de quien visita la página. Por eso en font-family se escribe una lista separada por comas: el navegador usa la primera que encuentre instalada. Al final de la lista se pone siempre una familia genérica (serif, sans-serif o monospace), que siempre existe. Si el nombre de la fuente tiene espacios, va entre comillas: "Courier New".

Herencia de color y fuente

Algunas propiedades, como color, font-family y font-size, las heredan los elementos que están dentro. Si se escribe body { font-family: Arial, sans-serif; }, todos los párrafos, títulos y celdas de la página usan Arial, sin tener que repetirlo en cada uno. background-color no se hereda, pero como el fondo de los elementos es transparente por defecto, se ve el color del elemento que los contiene.

Las tres formas de aplicar CSS a una página

Las reglas CSS se pueden escribir en tres lugares distintos. Las tres usan la misma sintaxis de propiedad y valor, pero cambia dónde se escriben y a cuántos elementos o páginas afectan.

1. Hoja de estilos externa

Las reglas se escriben en un archivo aparte con extensión .css, por ejemplo estilos.css. Ese archivo contiene solo CSS: no lleva <!DOCTYPE>, ni <html>, ni <style>. El documento HTML se conecta con el archivo mediante la etiqueta <link>, que va dentro de <head>:

index.html

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Mi página</title>
    <link rel="stylesheet" href="estilos.css">
</head>
<body>
    <h1>Bienvenidos</h1>
    <p>Texto de la página.</p>
</body>
</html>

estilos.css (mismo directorio)

body {
    font-family: Arial, sans-serif;
    background-color: #F4F6F7;
}

h1 {
    color: navy;
    text-align: center;
}
  • <link> es una etiqueta vacía: no tiene cierre.
  • rel="stylesheet" indica que el archivo enlazado es una hoja de estilos.
  • href es la ruta del archivo. Si estilos.css está en la misma carpeta que el HTML, basta el nombre. Si el nombre o la carpeta no coinciden exactamente, el navegador no encuentra el archivo y la página se ve sin estilos, otra vez sin ningún mensaje de error.

Ventaja principal: un mismo archivo .css se enlaza desde todas las páginas del sitio. Para cambiar el color de los títulos de 20 páginas se edita una sola línea en un solo archivo. Además, el navegador guarda en su memoria temporal (caché) el archivo .css la primera vez que lo descarga y lo reutiliza en las demás páginas del sitio.

Verifique: ¿Cuál es la forma correcta de enlazar una hoja externa?

2. Hoja de estilos embebida (interna)

Las reglas se escriben dentro de la etiqueta <style>, que va dentro de <head>. Afectan solo a ese documento.

<head>
    <meta charset="UTF-8">
    <title>Mi página</title>
    <style>
        h1 {
            color: darkred;
        }
        p {
            font-size: 18px;
        }
    </style>
</head>

Es útil cuando una sola página necesita estilos propios, o para hacer pruebas rápidas. Su desventaja es que, si el sitio tiene varias páginas, hay que copiar el mismo bloque en cada una, y cualquier cambio hay que repetirlo en todas.

3. Estilo en línea

La declaración se escribe directamente en el atributo style de un elemento. No hay selector ni llaves, porque el estilo se aplica solo a ese elemento:

<p style="color: green; text-align: center;">Este párrafo va centrado y en verde.</p>
<p>Este párrafo no se ve afectado.</p>

Es la forma menos recomendable para un proyecto real: vuelve a mezclar presentación y contenido en la misma línea, y para cambiar un estilo hay que buscarlo elemento por elemento. Se usa en casos puntuales, o para hacer una prueba rápida sobre un solo elemento.

La cascada: qué pasa cuando dos reglas se contradicen

Es normal que un mismo elemento reciba estilos de varios lugares a la vez. Si las reglas piden cosas distintas (una el color y otra el tamaño), se aplican todas. El problema aparece cuando dos reglas le asignan un valor diferente a la misma propiedad del mismo elemento. El navegador resuelve ese conflicto con un orden de prioridad llamado cascada. Para lo que se ve hoy, basta con tres reglas:

  1. El estilo en línea gana sobre las reglas de la hoja externa y de la embebida.
  2. Entre la hoja externa y la embebida, gana la que aparece de última en el <head>. No gana por ser de un tipo u otro, sino por su posición.
  3. Dentro de una misma hoja, si dos reglas con el mismo selector se contradicen, gana la última.

Es frecuente encontrar la afirmación de que "la hoja embebida siempre le gana a la externa". No es así. Las dos tienen la misma prioridad, y lo que decide es el orden en que aparecen en el documento. Casi siempre el <link> se escribe antes del <style>, y por eso parece que la embebida gana. Si se invierte el orden, gana la externa.

Ejemplo. Con este documento y esta hoja externa, ¿de qué color queda cada título?

index.html

<head>
    <meta charset="UTF-8">
    <title>Cascada</title>
    <link rel="stylesheet" href="estilos.css">
    <style>
        h1 { color: green; }
        h2 { color: purple; }
        h2 { color: orange; }
    </style>
</head>
<body>
    <h1>Primer título</h1>
    <h1 style="color: red;">Segundo título</h1>
    <h2>Subtítulo</h2>
</body>

estilos.css

h1 {
    color: blue;
    font-size: 40px;
}
  • Primer título: verde. La embebida está después del <link>. El tamaño de 40px sí se aplica, porque nadie lo contradice.
  • Segundo título: rojo, por el estilo en línea. También mide 40px.
  • Subtítulo: naranja. Dentro de la misma hoja, la última regla h2 gana.

Verifique: En el <head> aparece primero <style> p { color: gray; } </style> y después <link rel="stylesheet" href="estilos.css">. El archivo tiene p { color: black; }. Ningún párrafo tiene estilo en línea. ¿De qué color quedan los párrafos?

Verifique: La hoja embebida dice h1 { color: navy; font-size: 30px; } y el título es <h1 style="color: red;">. ¿Cómo se ve?

Cómo comprobar qué regla ganó

Todos los navegadores modernos tienen herramientas de desarrollador. Se abren con la tecla F12, o con clic derecho sobre un elemento y "Inspeccionar". En la pestaña de estilos aparecen todas las reglas que afectan al elemento seleccionado. Las declaraciones que perdieron el conflicto se muestran tachadas, y al lado de cada regla aparece de dónde viene (el nombre del archivo .css, la hoja embebida o el atributo style). Es la forma más rápida de saber por qué un estilo no se está aplicando.
